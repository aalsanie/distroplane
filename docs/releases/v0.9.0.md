# Distroplane v0.9.0

Distroplane distributes prebuilt release artifacts to npm, SDKMAN, custom Homebrew taps, and WinGet. This is the first non-release-candidate version of the 0.9 series.

## Changes since v0.9.0-rc.2

- **Safer recovery:** Journals now bind a run to its immutable plan ID. Reusing a journal with a different plan is rejected, even when operation IDs match (#51).
- **Missing credentials:** Operations blocked before provider dispatch can resume with the original plan and journal after credentials are restored, without consuming publication retries or rerunning completed operations (#52).
- **npm:** An ambiguous publish response cannot trigger an automatic republish. After a successful reconciliation reports the version absent, an operator may explicitly authorize one retry and acknowledge residual duplicate-publication risk (#53).
- **SDKMAN:** Supports the State API using vendor email/password authentication and a short-lived JWT, while retaining the explicit legacy vendor API integration (#54).
- **WinGet:** Supports ZIP archives containing portable, EXE, or MSI installers, validates nested installer paths and archive contents, and observes merged manifest content before reporting publication (#55).
- **Homebrew:** Supports complete JVM application distributions, installing launchers and runtime JARs together under `libexec`, with an explicit Java runtime dependency (#56).
- **Documentation:** CLI, provider behavior, recovery, security, and installation guidance were updated (#57).

## Important upgrade notice: release-candidate journals

**Journals written by v0.9.0-rc.1 or v0.9.0-rc.2 are not compatible with v0.9.0.** Journal schema v2 requires the original plan ID in the initial `RUN_STARTED` event; earlier schema-v1 journals do not provide that binding. Distroplane 0.9.0 rejects them for `apply`, `reconcile`, `status`, and `evidence`. There is no automatic migration.

If an earlier candidate started a release that might have reached an external destination:

1. Preserve its original plan, journal, artifacts, and provider binaries. Do not pair its journal with a new plan.
2. Independently inspect the affected npm registry, SDKMAN version, Homebrew tap, or WinGet repository and establish whether publication or review-side effects occurred.
3. Resolve any uncertain external outcomes before creating a replacement 0.9.0 run. Starting a new journal **does not** cancel or recover the previous publication attempt.

For recovery details, see the [CLI and recovery guide](https://github.com/aalsanie/distroplane/blob/v0.9.0/docs/cli.md).

## Installation

Download Distroplane and the provider executables you need for your operating system and architecture from **this release**, along with `SHA256SUMS`. Verify each executable against the manifest before putting the CLI and providers on `PATH`.

Release executables are built for Linux, macOS, and Windows on amd64 and arm64. `RELEASE-METADATA.json` records the release version, source commit, build date, Go toolchain, and CGO setting. The checksum manifest and metadata are unsigned; matching a checksum does not independently authenticate the release publisher.

The GitHub Action can install the matching release executables using `aalsanie/distroplane@v0.9.0`. Install and plan/apply instructions are in the [release verification guide](https://github.com/aalsanie/distroplane/blob/v0.9.0/docs/release-verification.md) and [README](https://github.com/aalsanie/distroplane/blob/v0.9.0/README.md).

## Publication and recovery limits

Distroplane plans and distributes existing artifacts; it does not build or host them. Published plans contain absolute local artifact paths and provider executable digests. Preserve the planned artifact bytes and provider binaries until the run completes.

An npm timeout can leave publication uncertain even if a subsequent lookup shows the version absent. SDKMAN State API acceptance is not proof of public client availability. A WinGet pull request is not a completed publication until the planned manifest contents are observed on the destination base branch.

Distroplane does not guarantee exactly-once delivery, automatically roll back external changes, or sign evidence. See the [security model](https://github.com/aalsanie/distroplane/blob/v0.9.0/docs/security-model.md).
